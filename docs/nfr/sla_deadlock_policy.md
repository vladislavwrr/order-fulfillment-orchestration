# Нефункциональные требования (NFR), SLA/SLO и регламент обработки сбоев

## 1. Метрики доступности и производительности (SLA / SLO)

| Компонент / Сервис | Целевой SLO (Доступность) | Максимальный Latency (p99) | Расчетный SLA |
| :--- | :--- | :--- | :--- |
| **Order Orchestrator Engine** | **99.95%** | $\le 200\text{ мс}$ | 99.9% (допустимый простой $\le 43$ мин/мес) |
| **WMS API (`/reserve`, `/release`)** | **99.9%** | $\le 400\text{ мс}$ | 99.5% |
| **Payment Gateway API** | **99.99%** | $\le 1000\text{ мс}$ | 99.9% |
| **Delivery Webhook Receiver** | **99.9%** | $\le 300\text{ мс}$ | 99.5% |

### Расчет Error Budget
* При объеме $100\,000$ заказов в месяц и SLO $99.95\%$ бюджет допустимых технических ошибок составляет **не более 50 заказов в месяц**.

## 2. Политика повторов (Retry & Circuit Breaker)

* **Идемпотентность:** Все запросы на списание (`POST /payments/capture`) и создание задач доставки (`POST /delivery/tasks`) передают заголовок `X-Idempotency-Key: {order_id}`.
* **Retry Strategy в Camunda:** 
  * Для сетевых сбоев (HTTP 502/503/504, Connection Timeout): `3 попытки` с экспоненциальной задержкой (`PT5S`, `PT20S`, `PT60S`).
  * Для бизнес-ошибок (HTTP 400, 422): **Retries = 0** (мгновенный переход на компенсирующую ветку BPMN).

## 3. Регламент разбора инцидентов и Deadlock Policy

1. **Мониторинг:** Алертинг в Grafana / Prometheus срабатывает, если количество активных инцидентов в Camunda превышает 5 штук за 5 минут.
2. **Действия дежурного инженера (L2 Support):**
   * Открыть инстанс процесса в **Camunda Cockpit**.
   * Проверить внешний статус платежа в биллинговой консоли по `order_id`.
   * **Сценарий А (Деньги не списаны):** Выполнить *Cancel Process Instance* $\to$ запустить компенсирующую таску `WMS Release` $\to$ уведомить клиента.
   * **Сценарий Б (Сбой был временным, деньги списаны):** Нажать *Retry Job* в админке для продолжения выполнения процесса по цепочке сборки.
3. **Deadlock Timeout:** Любой зависший инстанс без внешнего вебхука доставки закрывается автоматически через 72 часа переводом в статус `STALLED_FOR_REVIEW`.
